# Quivers - Official Website

A modern, responsive website for **Quivers**, the cathartic jangle pop band from Melbourne, Australia. Plain HTML pages and CSS, with TypeScript adding a merch store, music player and other content from the Quivers API.

## About Quivers

Quivers have been creating cathartic jangle pop for long enough to receive support from Pitchfork, NPR, JJJ, and even R.E.M., who once sent fire emojis in their DMs. The band has performed at major festivals including Dark Mofo, Meadow, Boogie, and SXSW, and filmed a session for Seattle's beloved KEXP station. They've supported acts like The Hold Steady, Sonny & the Sunsets, and Methyl Ethel.

Their latest album **"Oyster Cuts"** was released worldwide via Merge Records on August 9th, 2024, featuring a tougher and more expansive pop sound with both Bella and Sam sharing singing duties.

## Website Features

- **Merch store**: products, options (size, colour), "name your price", cart and card checkout via Stripe
- **Payment links (QR codes)**: the band charges any amount from the admin; the customer scans the QR code, can add a tip and pays by card
- **Music player**: plays the band's playlist on every page and keeps playing as you move between pages
- **Band info and look from the API**, edited in the MusicPowered admin: bio, line-up, contact details, social and streaming links, highlight colour, logo, band photos, page backgrounds and the Google Analytics ID
- **Mailing list signup** (footer) and a **contact form**
- **Tour dates** from Bandsintown
- **Works without the API**: every page is complete HTML with its own copy of the bio, line-up, logo, photos, backgrounds and teal; if the API can't be reached, the store points to Bandcamp and the rest of the site still works (but Google Analytics doesn't start, as its ID comes from the API)
- **Responsive**: desktop, tablet and mobile

## How It Works

- The HTML pages hold all the static content. `src/` (TypeScript) is bundled by esbuild into one script, `js/app.js`, which every page loads.
- Data comes from the Quivers API (`https://api.quiversmusic.com`, the MusicPowered backend). The API client in `src/api/quivers-api.ts` is generated by [Orval](https://orval.dev) from the API's OpenAPI spec. Don't edit it by hand.
- The band's look comes from the API's About record (`/about/user/slug/quivers`) and is applied by `src/site/theme.ts`:
  - **Highlight colour** (`highlight_colour`) replaces the `--highlight` colour in the stylesheet, and is also used for the Bandsintown widget and the Stripe card fields.
  - **Images**: an `<img data-band-image="main_logo">` shows that About field's image (`main_logo`, `band_photo_url`, `contact_img`), keeping its own `src` if the field is empty or fails to load. The logo is always shown white (a CSS filter), so it should be uploaded with a transparent background.
  - **Page backgrounds**: `<body data-band-background="about_bg_img">` shows that field's image behind the page; the `<body>` class picks the local plant used without it. Home uses `tour_bg_img`, About `about_bg_img`, Contact `contact_bg_img`, and Music, Merch and the store pages `music_club_img`.
  - **Google Analytics** starts with the About record's `ga_tag` (`src/lib/analytics.ts`), so there's no tracking code in the pages.
- The bio (`content`) and band members (`/band-member/user/…`) on the About page also come from the API.
- The Contact page's details (`/contact-details/user/…`) are one block of rich text in the admin. `src/pages/contact.ts` splits it into the page's cards: each line that's all bold ("Enquiries:") starts a new card headed by that line.
- The band's links (`/footer-links/user/…`) replace the footer's social icons, and the music services among them (Bandcamp, Spotify, Apple Music, YouTube) replace the Music page's "Stream & Buy" cards (`src/components/band-links.ts`). Each link's icon is a Font Awesome name from the admin (`facebook-f`, `apple`, …); a name the site has no icon for gets a plain link icon in the footer and no Music page card. The Merge Records card isn't in the API, so it stays in `music.html`.
- `mediaHosts` in `src/config.ts`: photos and audio are in the `cdn2.musicpowered.net` S3 bucket, but that domain has lapsed, so they're loaded from the bucket's S3 address.
- Links between pages swap the page content in place (`src/site/router.ts`) so the music keeps playing. Anything unexpected falls back to a normal page load.
- The cart and checkout follow the MusicPowered web app: Stripe card payment (`POST /payments`), then the order (`POST /order`), the order email (`POST /notifications/order`) and a total check (`POST /order/verify`). Shipping is charged once per order at the highest shipping cost of anything in it, using the band's postage regions (looked up from the address with Google's Geocoding API).
- Payment links are "custom orders" in the API. In the admin (Orders) the band creates one for an amount and note, and shows the customer its QR code, which opens `order.html?id=<custom order id>`. The page (`src/pages/order.ts`) loads it (`GET /custom-orders/{id}`), takes the card payment (`POST /payments`, in the order's currency, plus any tip), marks it paid (`PUT /custom-orders/complete`) and emails the band (`POST /notifications/custom_order`). The API only returns links that are unpaid, unrefunded and not deleted, so a link can't be paid twice. Older QR codes point at `/order/<id>`: `404.html` forwards those to `order.html?id=<id>`.

## File Structure

```
Quivers-Web/
├── *.html                   # The pages
├── styles.<hash>.css        # Stylesheet
├── images/                  # Photos, logo, background plants
├── src/                     # TypeScript, bundled into js/app.js
│   ├── main.ts              # Starts everything
│   ├── config.ts            # Band slug, API URL, etc.
│   ├── api/                 # Generated API client + axios setup
│   ├── data/                # Band data, cart, merch, shipping
│   ├── pages/               # Code for each page (by <body data-page>)
│   ├── components/          # Product cards, add to cart, forms, icons
│   ├── player/              # Music player
│   ├── site/                # Navigation, loader, lightbox, dialogs, router
│   └── lib/                 # Small helpers
├── scripts/                 # build.ts and dev.ts (run by yarn)
├── dev/                     # Sample-data API for local development
├── orval.config.ts          # API client generation
├── cacheBust.sh             # Renames CSS/images so browsers refetch them
└── .github/workflows/       # Build and deploy to GitHub Pages
```

## Development

Needs Node.js 22.18 or later (see `.nvmrc`) and [Yarn 1](https://classic.yarnpkg.com/) (`brew install yarn`). The project uses Yarn only: `npm install` is refused (`devEngines` in `package.json`), and `yarn.lock` is the lockfile.

```sh
yarn install
yarn start          # http://localhost:8080, rebuilds and reloads on changes
```

`yarn start` uses sample data from `dev/mock-api.ts`, so the store, player and forms all work locally. Sample payment links: `order.html?id=sample-payment` (with a note) and `order.html?id=sample-no-note`; paying one uses it up until you restart `yarn start`. Payments there always succeed without charging anything (the sample Stripe key is fake, so the card fields won't accept input). Options:

```sh
MOCK_API_DOWN=1 yarn start               # see how the site copes without the API
API_URL=http://localhost:8088 yarn start # use the real API running locally
PORT=3000 yarn start
```

The real API only accepts requests from `quiversmusic.com` and `http://localhost` (port 80), so to use it locally run `PORT=80 API_URL=https://api.quiversmusic.com GOOGLE_MAPS_API_KEY=… yarn start` and open http://localhost. That's the live store with live Stripe keys: don't complete a payment unless you mean to.

Other commands:

```sh
yarn typecheck     # TypeScript checks for src/ and the scripts
yarn build         # Production build into _site/ (set GOOGLE_MAPS_API_KEY)
yarn api-generate  # Regenerate src/api/quivers-api.ts from the live API spec
```

To generate the API client from a saved copy of the spec: `API_SPEC=./openapi.json yarn api-generate`.

## Deployment

Pushing to `main` runs `.github/workflows/deploy.yml`: it type-checks, builds `_site/` (the pages, CSS, images and a minified `js/app.<hash>.js`), and publishes it to GitHub Pages. The built JavaScript is never committed.

One-time setup: in the repository's **Settings → Pages**, set **Source** to **GitHub Actions** (and keep the custom domain `quiversmusic.com`).

Add a repository secret named `GOOGLE_MAPS_API_KEY` (Settings → Secrets and variables → Actions): the Google Geocoding key used to find the customer's postage region. The build fails without it, because checkout would charge the wrong shipping. The key ends up in the public site script, so restrict it in Google Cloud to the `quiversmusic.com` referrers and the Geocoding API. Optional repository variable: `API_URL` (defaults to `https://api.quiversmusic.com`).

Run `./cacheBust.sh` before deploying when the CSS or images change, as before. The script bundle gets a new name automatically on every build.
